# FEFO Traceability

Аналитическое приложение для автоматизации прослеживаемости партий товаров на складе и оптимизации ротации запасов по срокам годности на основе принципа FEFO (First Expired, First Out).

## 1. Назначение проекта

Система предназначена для учёта товаров и партий, контроля сроков годности, размещения запасов по складским ячейкам и регистрации перемещений.

## 2. Архитектура

Проект состоит из трёх основных компонентов:

- **Клиент:** приложение для macOS, разработанное на Swift и SwiftUI.
- **Сервер:** REST API на Vapor 4.
- **База данных:** PostgreSQL с использованием Fluent ORM.

Обмен данными между клиентом и сервером выполняется посредством HTTP-запросов и JSON.

Клиентская часть использует архитектурные подходы MVVM, Repository и Dependency Injection. Бизнес-логика реализована на серверной стороне.

## 3. Основные возможности

- Регистрация и авторизация пользователей.
- Разграничение доступа на основе ролей.
- Учёт товаров и партий.
- Учёт складов и мест хранения.
- Размещение партий в ячейках.
- Регистрация складских перемещений.
- Получение списка партий с учётом FEFO.
- Просмотр аналитических показателей.

## 4. Структура проекта

- `client/` — клиентское приложение SwiftUI.
- `server/` — сервер Vapor, контроллеры, сервисы, модели и миграции.
- `scripts/` — вспомогательные скрипты.
- `FEFOTraceability.xcworkspace/` — рабочее пространство проекта.

## 7. Настройка базы данных

Перед запуском сервера необходимо запустить PostgreSQL и создать базу данных `fefo_traceability`.

Параметры подключения задаются переменными окружения:

| Переменная | Значение по умолчанию |
|---|---|
| `DATABASE_HOST` | `127.0.0.1` |
| `DATABASE_PORT` | `5432` |
| `DATABASE_USERNAME` | значение переменной `USER`, иначе `postgres` |
| `DATABASE_PASSWORD` | пустая строка |
| `DATABASE_NAME` | `fefo_traceability` |

При необходимости параметры можно задать перед запуском сервера. Реальные пароли не следует сохранять в репозитории.

## 8. Запуск сервера

В первом окне Terminal:

    cd ~/Documents/fefo-traceability/server
    swift run

При запуске сервер выполняет зарегистрированные миграции базы данных.

Проверка доступности сервера:

`http://127.0.0.1:8080/api/health`

## 9. Запуск клиента

Во втором окне Terminal:

    open "$HOME/Documents/fefo-traceability/FEFO Traceability.app"

Сервер должен быть запущен отдельно. Клиент обращается к API по адресу `http://127.0.0.1:8080/api`.

## 10. Основные маршруты API

| Назначение | Маршрут |
|---|---|
| Проверка сервера | `GET /api/health` |
| Регистрация | `POST /api/auth/register` |
| Авторизация | `POST /api/auth/login` |
| Текущий пользователь | `GET /api/auth/me` |
| Товары | `/api/products` |
| Партии | `/api/batches` |
| Склады | `/api/warehouses` |
| Места хранения | `/api/storage-locations` |
| Размещение партий | `/api/batch-placements` |
| Перемещения | `/api/stock-movements` |
| FEFO | `GET /api/fefo` |
| Аналитика | `GET /api/analytics` |

Для защищённых маршрутов требуется Bearer-токен. Доступ к операциям ограничивается ролями пользователей.

## 11. Статус проекта

Проект находится в разработке. Для развёртывания клиента и сервера на разных физических узлах необходимо настроить сетевой адрес API и параметры подключения к базе данных.
